# Markup anchoring — handoff

Context for whoever picks up "pencil markup should stay with its note".
Two attempts were made and both were reverted. The idea works; the way it
was integrated does not. This is what was learned so it isn't learned twice.

## The problem

Ink is stored as a **bitmap** — a PNG data URL scaled to the paper, one per
score at `cookie:${scoreId}:ink`. Undo history is an array of those data
URLs (`inkHistory` ref + `inkIndex` in `ScoreViewer.tsx`).

So when a view setting re-lays the music, the notes move and the photograph
of the ink does not. Circle a note, change notation size, and the circle is
now around a different note.

## What was tried

**Attempt 1.** Record stroke points alongside the bitmap; anchor each stroke
to the nearest note; repaint anchored strokes after a re-layout.

It worked, measurably: a circle drawn around note 20 stayed on it when
notation size went 1.25 → 0.75 and that note moved **327px**. Offset from
its note before: (−1, −2). After: **(0, 0)**.

It also broke eraser, undo, clear, arrow, text boxes and sticky notes. The
repaint was a `useEffect` with **no dependency array**, so it ran after every
render and repainted over every edit the moment it happened. Reverted.

**Attempt 2.** Same, but the repaint keyed to `[layoutVersion]` (see
Gotchas). Added: undo drops the last recorded stroke, clear drops all, the
eraser retires all recorded strokes (there is no way to know which ones it
rubbed out), and pressure is stored per point so a repaint reproduces the
nib instead of a hairline.

All five tools passed automated checks. In real use it still misbehaved —
undo blinked, system-spacing changes didn't re-anchor. Reverted at the
user's request.

## Why it kept failing

**Two systems owned the same ink.** Every stroke lived in both the bitmap
history and the vector list. Undo restored from one while the repaint drew
from the other, so they fought. No amount of patching fixes that — the
vectors have to *replace* the bitmap, not sit beside it.

That is the whole lesson. Do the replacement as one piece of work, on a
branch, rather than incrementally in the working copy.

## What survives

`app/flute-studio/lib/inkStrokes.ts` — pure anchoring maths, currently
**wired to nothing**. This is the part that demonstrably worked. Types plus:

- `noteSpots(root, paperRect, size)` — note positions in paper units
- `systemSpots(...)` — staff-line tops, for marks that belong to no note
- `anchorFor(point, spots, systems)` — pin a point to note / system / paper
- `placeStroke(stroke, spots, systems)` — where its points belong now

## Design already agreed with the user

- **Anchor the stroke, not the points.** One anchor moves it rigidly (a
  circle stays a circle). Two anchors also stretch it horizontally between
  them (a slur still spans the right notes when spacing changes).
- Within **46px** of a notehead → note anchor. Horizontal reach over
  **60px** → anchor both ends. Nothing near → **staff line**, so a margin
  comment moves down when the lines above it grow but never scales.
- A stroke whose note is gone (the exercise changed underneath it) is
  **skipped**, not dropped somewhere arbitrary.
- **Zoom**: strokes stored in paper units scale with the music, so a circle
  keeps its size relative to its note at any magnification.
- **Text boxes belong in the same undo stack.** That is the convention in
  every annotation app, and the user asked for it. Typing must be
  **coalesced** — one undo step per burst, not one per keystroke. This is
  the same refactor: today's undo is a stack of canvas snapshots, and text
  boxes are DOM/React state, so they cannot go in one. It has to become a
  stack of *document states*.
- **Highlighter** falls out for free once strokes are vectors — a wide,
  low-alpha stroke with multiply blending.
- Do **not** add shape recognition. The user explicitly does not want
  strokes straightened or fitted; replay the points as drawn.
- T/K articulations are **generated by the app**, not markup. Don't
  re-implement them by hand.

## Storage, since it was a worry

Bitmaps are the expensive option, not vectors:

| stored ink | size |
| --- | --- |
| `ditto` | 420 KB |
| scale book | 302 KB |
| held notes | 112 KB |
| **three scores** | **834 KB** |

That is about a sixth of the localStorage budget for three annotated
pieces — a PNG stores every pixel of an empty page. The same drawing as
point arrays is roughly **100× smaller**.

Migration: existing bitmaps cannot be converted into strokes. Either keep
the old bitmap as a read-only layer underneath the new vector ink, or
discard it. Ask before discarding.

## Bugs found on the way that ARE fixed — leave them alone

These are unrelated to anchoring and are in the tree:

1. **Duplicate copies of markup after a view change.** `sizeInkCanvas`
   restores saved ink asynchronously; every view-setting change calls it
   again, and a slider drag calls it many times. Each pending load drew onto
   the same canvas at whatever size it had measured, and `drawImage` does
   not clear. Fixed with a generation stamp on the canvas — a superseded
   load drops its result.
2. **Text and sticky notes could not be typed into.** `noteDown` calls
   `setPointerCapture`, which re-targets `pointerup` to the capturing
   element, so `noteUp`'s "focus the textarea if the press didn't move"
   never fired. It now remembers which field the press landed on.
3. **Notes vanished.** `notesRef` was only updated inside `persistNotes`,
   but the load effect and `noteMove` set state without it — so when a drag
   ended, `noteUp` wrote a stale (often empty) array back to storage and
   deleted every note on the page.
4. **Undo blinked the whole page of markup away and back.** `showHistory`
   cleared the canvas, then loaded the replacement image asynchronously,
   leaving a blank frame. It now decodes first and clears+draws together.
5. **Palm rejection**, plus an "Apple Pencil only" setting in the account
   menu (`lib/pencilMode.ts`).
6. **Tap slop** — SVG hit-testing only registers on the painted glyph, so a
   tap a few pixels off a notehead hit nothing. Taps (not hovers) fall back
   to the nearest notehead within 16px.

## Gotchas

- **Repaint trigger**: `layoutVersion`, bumped by `mountMarksLayer()` which
  `resync()` calls once the music has been re-engraved. Never a bare
  `useEffect` with no dependency array — that is what broke attempt 1.
- **Coordinate space**: `point(e, canvas)` converts a pointer event into
  paper units. Store strokes in those units.
- **Z-order**: the ink canvas is z-index 8 and `pointer-events:none` unless
  annotating; score notes are z-index 9, so they stay clickable.
- **Ink is restored on load**, so any test that measures canvas pixels must
  clear first or it measures old strokes.
- **Testing in the Claude browser pane**: the click coordinate frame is
  800px wide against a 935px page — a factor of ~0.855. Clicks aimed with
  `getBoundingClientRect` land ~15% off unless converted. This invalidated
  several measurements during the session.
- Verify by **counting marks in the DOM first**, then pairing them to notes.
  Pairing heuristics that match on x alone, or with a tight vertical window,
  will pair a mark to a note on a different staff line or miss notes with
  ledger lines.
